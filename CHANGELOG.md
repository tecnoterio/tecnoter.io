# Changelog

Notable changes to tecnoter.io, newest first.

The project has no release tags, so entries follow the commit history. Dates are
the dates work landed, not releases.

---

## 2026-10-01 — Zola replaces Hugo

The site is now built by Zola instead of Hugo, so the whole thing runs in Rust:
one language for the terminal and the static site. Nothing about the terminal,
the URLs, or the dual-mode behaviour changed.

**Why.** Two languages for one site was tolerable when the second was a
build-time concern. With Zola it is a single toolchain, and the terminal's data
feed is generated the same way the pages are.

### How it was done

The port was small — about eight template files. Every obstacle was a Tera/Hugo
syntax difference rather than an architectural one. The non-obvious ones:

- `templates/_default/` does not exist; it is `page.html` and `section.html`
- There is no `jsonify` filter, so JSON cannot be embedded from a template
- `get_section` takes a file path (`posts/_index.md`), not a slug
- A function call cannot be chained with a property — `{% set %}` first
- `page.group` parses as Tera's built-in `group` filter, so `group` is unusable
  as a front-matter key
- Zola has no per-page output format, so per-page JSON is generated by script
- Zola builds no taxonomy pages unless `taxonomy_list.html` and
  `taxonomy_single.html` exist, and it fails silently if they do not
- `zola build` clears `public/`, so the WASM build has to target `static/`

The full write-up, including the Markdown-to-plaintext rules needed to match
Hugo's `.Plain` byte for byte, is in
[`docs/hugo-to-zola-migration.md`](docs/hugo-to-zola-migration.md).

### Fixed along the way

- **Terminal could not read any page.** `cat` fetches `<url>/index.json`, which
  Hugo produced from `single.json` and Zola did not produce at all. Every
  `cat bio` and every hub link that loaded content 404'd. Those files are now
  generated after the build.
- **WASM failed to deserialize the site state.** `fortunes` is
  `[{"text":"..."}]` in JSON, but `SystemState` had it as `Vec<String>`. Added a
  `Fortune` struct.
- **Taxonomy pages were missing.** `ls /` advertises `/tags` and
  `/categories`, but neither was generated. All 8 URLs now match the old set.

### Removed

- `hugo.toml`, `themes/`, `layouts/`, `archetypes/`, `.github/workflows/hugo.yml`
- `Makefile.zola` — the Zola makefile *is* `Makefile` now. Dropped the
  `snapshot-golden` target, which invoked the deleted Hugo, and `build-index`,
  which was already a step inside `build`
- `CLAUDE.md`, merged into `AGENTS.md`. Two files to keep accurate, one of them
  describing a setup that no longer existed
- `shell_wasm/src/main.rs`, a binary that shelled out to `cargo run` from a
  `main()` that would have called it again
- A backup of the deleted Hugo layouts

### Changed

- `content/` and `data/` are no longer duplicated into a subdirectory. The Zola
  project was first built in `zola_spike/` alongside Hugo; it now lives at the
  repository root and both symlinks are gone.
- Content front matter is TOML (`+++`), not YAML. Posts carry both a top-level
  `tags` key (Hugo's shape) and a `[taxonomies]` table (Zola's).
- A parity gate now runs in `make build`: the generated JSON is compared against
  a committed reference, and the build fails on drift. After an intentional
  content edit, run `make accept-content`. It runs in CI too, so a content
  regression fails the pull request rather than only a local build.

### Pull request previews

Each PR now publishes to a `/<repo>/pr-<n>/` subfolder, and the subfolder is
removed when the PR closes. Production deploys the site root and preserves any
open previews.

This required changing how the site is published. Per-PR subfolders need a
branch to push into, and Pages serves one location, so the previous
`actions/deploy-pages` setup could not be extended into it — the site now
publishes to a `gh-pages` branch. **Repository settings must move Pages source
to "Deploy from a branch"**, or the deploy goes green without updating anything.

The site was root-absolute throughout and could not have run in a subfolder:
27 references across the templates, a hardcoded `index.json` fetch in
`static/js/terminal.js`, and every `url` inside that file. They now resolve
through a base path supplied by `get_env`. The Rust terminal needed no change —
`cat` derives its fetch URL from `index.json`, so prefixing that one field
covers it, along with `bbs.js` and `commands.js`.

## 2026-02-19 — Content rewrite

Page copy rewritten across the site; `who.md` removed. Merged from
`improve-page-texts`.

This is what exposed the parity gate's value: five of six pages diverged under
Hugo's plain-text rules, which a diff caught and eyeballing would not have.
Three rules were recovered from those diffs — smartypants, hard line breaks,
and headings merging with the paragraph beneath them.

## 2026-02-10 — Hub mode

The static site mode. Hugo pages for the company content, a custom theme, a
hardware-panel aesthetic with amber/green/BW modes, and the CI/CD pipeline that
still — in Hugo form — deploys to GitHub Pages.

---

## 2026-01-06 — Rust terminal, early

The shell kernel moved to Rust compiled to WebAssembly, replacing a JavaScript
command processor. `static/js/` is the display driver; the WASM module owns
command parsing, the virtual filesystem, and session state.

## 2023-12 — Jekyll origin

Initial commit. A Jekyll site, before either the terminal or the WASM shell.
